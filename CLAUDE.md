# CLAUDE.md — Контекст проекта для ИИ-ассистента

## Что это за проект
Агент-ассистент для нутрициолога (Health & Wellness Coach).
Два режима работы:
- Режим нутрициолога: аналитика клиентов, управление планами, сводки
- Режим клиента: ежедневный диалог, дневник питания, фото еды, голосовые сообщения

## Репозиторий
github.com/viktorsula/nutritionist-agent

## Деплой
Render: nutritionist-agent-gvxp.onrender.com

## Стек
- Python 3.10
- LangGraph (оркестрация агентов)
- Supabase (база данных)
- Streamlit (веб-интерфейс)
- Telegram Bot (основной канал)
- Groq / Claude Sonnet / Gemini Flash (LLM провайдеры)
- Langfuse (мониторинг)

## Архитектура
Входящее сообщение → router.py → business_rules (детерминированный слой) →
LangGraph агент → LLM → ответ → сохранить в Supabase

## Философия системы (ключевые решения)

### Роли и права
- Нутрициолог = единственный источник назначений и рекомендаций
- Агент = аналитик и советник для нутрициолога (предлагает, аргументирует)
- Клиент = исполнитель и информатор
- Observer = только чтение (зарезервировано для будущих клиник)

### Клиентоориентированность
Клиент общается КАК ЕМУ УДОБНО — агент адаптируется:
- Фото еды → Gemini Vision распознаёт → уточняет если нужно
- Текст ("съел салат") → агент уточняет состав и способ приготовления
- Голос (v1.1) → Whisper транскрибирует → далее как текст

### Контекстный стек агента (порядок сборки ответа)
```
[1] BUSINESS RULES         — всегда первым
    • Доступ, оплата, медицинские пороги
    • critical → стоп, LLM не вызывается

[2] ПЕРСОНАЛЬНЫЙ КОНТЕКСТ  — всегда, обязательно
    • Профиль клиента (аллергии, ограничения, цели)
    • Медицинский профиль
    • Активный план питания + wellness план
    • Активные задачи

[3] ИСТОРИЯ РАЗГОВОРОВ     — динамически (last_n)
    • Классификатор определяет объём по важности вопроса
    • Простой вопрос → 5-10 сообщений
    • Анализ динамики → 30+ сообщений + summary

[4] KNOWLEDGE BASE          — по типу запроса
    • Медицинский вопрос → ВСЕГДА
    • Рецепт/меню → если нужна точность

[5] CURATED WEB             — доверенные источники нутрициолога
    • Агент активно ходит на указанные сайты
    • Периодически кешируется в pgvector

[6] OPEN WEB                — последний резерв
    • Только для рецептов (после проверки профиля)
    • Только разрешённые сценарии

[7] LLM                     — синтез финального ответа
    • Groq llama-3.3-70b (диалог)
    • Claude Sonnet (аналитика)
    • Gemini Flash (фото/vision)
```

### Персональный контекст обязателен даже для общих вопросов
Любой ответ учитывает аллергии, ограничения и цели конкретного клиента.

## Хранилище данных

### Три уровня для каждого документа
```
Supabase Storage  → бинарный файл
PostgreSQL        → метаданные (кто, когда, какой файл)
pgvector          → эмбеддинги чанков (семантический поиск)
```

### Два физически разных хранилища
```
/documents/client_{id}/   ← анализы клиента (RLS защита)
/documents/knowledge/     ← библиотека нутрициолога (общий ресурс)
```

### Два типа веб-доступа агента
```
CURATED WEB   → нутрициолог добавляет URL в knowledge_base
                агент активно ходит за актуальным контентом
OPEN WEB      → только для рецептов, после проверки профиля клиента
```

## База данных (Supabase) — выполнено

### Блок 1: Пользователи и профили ✅
```
users              — роли: nutritionist / observer / client
clients            — воронка статусов + оплата + подписка
client_profiles    — медицинский профиль (allergies ≠ intolerances!)
wellness_plans     — Health Coaching: сон, спорт, восстановление, стресс

```

## Важные архитектурные решения

### allergies vs intolerances
- allergies → Business Rules БЛОКИРУЕТ продукт (severity: high/critical)
- intolerances → Business Rules ПРЕДУПРЕЖДАЕТ (severity: medium)

### Версионирование планов
- is_active = true → текущий план
- Старые версии не удаляются → полная история назначений
- effective_from / effective_to → точные даты действия

### История разговоров
- В БД храним ВСЁ (без лимита)
- В LLM передаём ВЫБОРКУ (last_n определяется классификатором)
- thread_id группирует сообщения одной сессии

### Оплата клиента
- payment_status: active / inactive (нутрициолог меняет вручную)
- subscription_start_date / subscription_end_date → даты периода
- При inactive → Business Rules блокирует доступ без вызова LLM

### meal_logged payload
```json
{
  "meal_type": "lunch",
  "input_source": "photo|text|voice",
  "original_input": "что написал/сказал клиент",
  "agent_clarified": true,
  "photo_url": "storage/...",
  "description": "описание блюда",
  "ingredients": ["ингредиент1"],
  "cooking_method": "способ приготовления",
  "calories": 420,
  "protein_g": 35,
  "fat_g": 8,
  "carbs_g": 45,
  "confidence": "high|medium|low",
  "interval_from_last_h": 4.5
}
```
